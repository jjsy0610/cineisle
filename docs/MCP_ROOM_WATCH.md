# MCP 挂机陪看

`watch_room` 把 CineIsle 的房间聊天、截图与当前 MCP 工具调用连接起来。它采用长轮询：单次最多等待 55 秒，有新事件就提前返回；没有事件则以心跳结果返回。AI 按返回的 `next_call` 继续调用，当前对话轮就能持续守候房间。

这不是后台推送。聊天窗口关闭、当前回答结束、MCP 连接断开或服务重启后，AI 不会在后台自行醒来；重新发起一次挂机陪看即可恢复。

## 推荐开场指令

```text
请挂机陪看房间 ABC123。收到聊天或新画面后自行决定是否回复；继续陪看时按 next_call 立即再次调用 watch_room，直到我在房间里说“散场”。
```

首次调用可以只传房间号：

```json
{
  "room": "ABC123"
}
```

工具会从调用时刻开始等待，默认监听：

- `message`：观影人在房间发出的聊天或弹幕
- `frame`：经过后端节流的低频画面更新
- `stop`：散场事件

每次返回都包含新的 `cursor` 与可直接复用的 `next_call`。有事件时会附带最新播放状态、字幕上下文和可选的最新画面。

## 结束陪看

观影人可在房间聊天发送以下任一条独立消息：

```text
散场
停止陪看
结束陪看
```

也可以由 AI 调用 `stop_watching`。散场只结束当前挂机链，不会删除房间、影片进度或聊天记录。

## 防回声与额度控制

- `ignoreAssistant` 默认为 `true`，AI 通过 `send_room_message` 写回的内容不会再次唤醒同一个 watcher。
- Android 仍可每 15 秒上传截图；后端默认每 45 秒最多发出一个 `frame` 事件，避免每帧都触发推理。
- 即使某张截图未单独触发 `frame`，下一条聊天到达时仍会附带房间的最新画面。
- 可通过环境变量 `CINEISLE_FRAME_EVENT_INTERVAL_MS` 调整画面事件间隔，最小为 15000 毫秒。

## 断线恢复

服务端事件游标保存在内存中。服务重启后游标会重新计数，但房间状态与最近画面仍按原有数据文件恢复。重新下达一次挂机陪看指令即可；首次不传 `cursor` 会从当下开始等待，不会把旧聊天全部重放。
